# [D03] Audit graph and reconciliation work budgets against real city sizes

> **Published tracking proposal:** [#108](https://github.com/xbwtyz/Mappo/issues/108) records this limitation or possible capability. This is **not** an approved implementation or assigned release.

**Group:** D · **Classification:** Intentional safety caps / scale proposal · **Suggested priority:** P3 · **Version:** Unassigned

## Current behavior and user impact

Valid extreme city inputs may exceed maximum node, road or work counts and some topology edits have lower block limits.

**Current technical limitation:** A1 has 20,000 node / 40,000 road / 6,000,000-work caps; topology reflow has a 32-block limit.

## Reproduction / evidence collection

Use reproducible city fixture sizes at/near current caps; measure actual failures before suggesting increased limits.

Reconfirm against the version planned for implementation, recording a deterministic seed, relevant IDs, browser and actual error message. The source reference indicates an implementation restriction, **not** that a user test was independently executed for this candidate.

## Desired outcome

Determine whether real supported Large cities approach these limits and safely scale bounded algorithms if justified.

## Draft acceptance criteria

- [ ] Record real city sizes, bound hit rates, runtime and memory on both desktop browsers.
- [ ] Retain finite work budgets and early cancellation; do not simply remove guardrails.
- [ ] Compare algorithm changes under equal fixtures and report worst-case latency.
- [ ] Preserve safe failure for pathological inputs and deterministic output.

## Dependencies and design boundary

A06; D02 profiling if performance-limited.

**Owner decision needed:** Treat as an audit, not a feature PR, unless real use cases are bounded by the current caps.

## Preservation and verification gates

Retain deterministic generation, one authoritative accepted city, preview/Cancel isolation, independent full validation before atomic Apply, stable provable identities, protected and unknown authored metadata, appropriate scoped Undo/Redo, and safe offline project round-trip. Any required schema migration, existing CI policy change, release or Pages publication needs **separate authorization**. Use targeted tests during development and full six-runner CI for the review-ready PR.

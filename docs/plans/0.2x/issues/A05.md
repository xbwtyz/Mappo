# [A05] Assess spline or curved-street geometry beyond editable polyline bends

> **Published tracking proposal:** [#97](https://github.com/xbwtyz/Mappo/issues/97) records this limitation or possible capability. This is **not** an approved implementation or assigned release.

**Group:** A · **Classification:** New capability / geometry model expansion · **Suggested priority:** P3 · **Version:** Unassigned

## Current behavior and user impact

Roads can be edited with a bounded number of polyline bends, but persisted true curves/splines are not implemented.

**Current technical limitation:** `ROAD_BEND_LIMIT = 24`; topology uses segmented road geometry.

## Reproduction / evidence collection

Draft a path with more than 24 bend points or request spline curvature instead of straight segments.

Reconfirm against the version planned for implementation, recording a deterministic seed, relevant IDs, browser and actual error message. The source reference indicates an implementation restriction, **not** that a user test was independently executed for this candidate.

## Desired outcome

Define a curved-road representation, rendering and snapping behavior that does not break graph/face/parcel semantics.

## Draft acceptance criteria

- [ ] Decide whether smooth display-only polylines satisfy the need or persisted curves are required.
- [ ] Document deterministic collision, widths, intersections, area/face calculation and save representation.
- [ ] Preserve existing paths and standalone output; any new project schema requires a separately approved migration decision.
- [ ] Test large cities, tight curvature, junction connections and old straight streets.

## Dependencies and design boundary

A03 intersection normalization, B01 polygon/general geometry where coupled.

**Owner decision needed:** Prefer display smoothing of existing polylines initially; true spline persistence is a separate data-model decision.

## Preservation and verification gates

Retain deterministic generation, one authoritative accepted city, preview/Cancel isolation, independent full validation before atomic Apply, stable provable identities, protected and unknown authored metadata, appropriate scoped Undo/Redo, and safe offline project round-trip. Any required schema migration, existing CI policy change, release or Pages publication needs **separate authorization**. Use targeted tests during development and full six-runner CI for the review-ready PR.

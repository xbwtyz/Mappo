# [B05] Improve author-preserving parcel decisions after large road changes

> **Published tracking proposal:** [#103](https://github.com/xbwtyz/Mappo/issues/103) records this limitation or possible capability. This is **not** an approved implementation or assigned release.

**Group:** B · **Classification:** Confirmed reconciliation limitation · **Suggested priority:** P1 · **Version:** Unassigned

## Current behavior and user impact

Otherwise reasonable road proposals can remain blocked when customized or provenance-unknown properties need relocation or explicit split/merge decisions.

**Current technical limitation:** Local reflow often blocks if a protected/custom parcel cannot be preserved with its existing frame; user-facing property choice handling is narrower than building conflict handling.

## Reproduction / evidence collection

Load a developed city with a named customized parcel, propose a road change through it, inspect the unresolved `parcel-decision-required` or related blocker.

Reconfirm against the version planned for implementation, recording a deterministic seed, relevant IDs, browser and actual error message. The source reference indicates an implementation restriction, **not** that a user test was independently executed for this candidate.

## Desired outcome

Offer audited owner choices for keeping, reshaping, transferring or retiring affected custom parcels while preserving protected data.

## Draft acceptance criteria

- [ ] Every authored parcel has a recorded provenance and explicit choice for destructive or identity-changing outcomes.
- [ ] Decisions never silently reassign buildings, plots, uses, names or extension fields.
- [ ] Blocked proposals remain editable; candidate transformations are shown against accepted geometry.
- [ ] Full-city validation and save/reopen prove one atomic transaction with stable unchanged records.

## Dependencies and design boundary

A06 local face lineage and B01–B04 general parcel geometry.

**Owner decision needed:** Which decisions are safe to automate for generated-only parcels, and which must always be explicit for authored records?

## Preservation and verification gates

Retain deterministic generation, one authoritative accepted city, preview/Cancel isolation, independent full validation before atomic Apply, stable provable identities, protected and unknown authored metadata, appropriate scoped Undo/Redo, and safe offline project round-trip. Any required schema migration, existing CI policy change, release or Pages publication needs **separate authorization**. Use targeted tests during development and full six-runner CI for the review-ready PR.

# [B03] Support partial-edge and irregular property merging

> **Published tracking proposal:** [#101](https://github.com/xbwtyz/Mappo/issues/101) records this limitation or possible capability. This is **not** an approved implementation or assigned release.

**Group:** B · **Classification:** Confirmed feature restriction · **Suggested priority:** P2 · **Version:** Unassigned

## Current behavior and user impact

Adjacent parcels often cannot be merged unless they share a full frontage-to-rear edge and form one convex four-corner result.

**Current technical limitation:** E3 requires compatible convex four-corner properties, a whole shared edge and aligned frontage.

## Reproduction / evidence collection

Select two valid parcels sharing only part of an edge and attempt E3 merge.

Reconfirm against the version planned for implementation, recording a deterministic seed, relevant IDs, browser and actual error message. The source reference indicates an implementation restriction, **not** that a user test was independently executed for this candidate.

## Desired outcome

Merge compatible irregular parcels across partial shared edges without deleting names, authored work or plot relationships.

## Draft acceptance criteria

- [ ] Specify supported adjacency and any concave union constraints.
- [ ] Prove no gap, overlap, cross-block ownership change or invalid road access.
- [ ] Show primary/secondary metadata policy and explicit retirement consent for conflicts.
- [ ] Validate buildings/plots, one-step Undo/Redo and portable save/reopen.

## Dependencies and design boundary

B01 polygon union support and B04 plot tiling.

**Owner decision needed:** Limit merges to the same block first; cross-block merges remain a distinct, likely road-topology operation.

## Preservation and verification gates

Retain deterministic generation, one authoritative accepted city, preview/Cancel isolation, independent full validation before atomic Apply, stable provable identities, protected and unknown authored metadata, appropriate scoped Undo/Redo, and safe offline project round-trip. Any required schema migration, existing CI policy change, release or Pages publication needs **separate authorization**. Use targeted tests during development and full six-runner CI for the review-ready PR.

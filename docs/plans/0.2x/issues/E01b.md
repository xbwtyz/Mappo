# [E01b] Add whole-city PNG export at selected resolution

> **Draft only:** Proposed future GitHub Issue. No GitHub Issue has been created yet.

**Group:** E · **Classification:** New output capability / known limitation · **Suggested priority:** P2 · **Version:** Unassigned

## Current behavior and user impact

PNG export saves only the canvas as currently displayed; users cannot export the entire city as one high-resolution map.

**Current technical limitation:** `downloadMapPNG4F` calls `canvas.toBlob`; the user guide explicitly notes visible-map-only output.

## Reproduction / evidence collection

Zoom into part of a city and export PNG; only the currently visible canvas area is exported.

Reconfirm against the version planned for implementation, recording a deterministic seed, relevant IDs, browser and actual error message. The source reference indicates an implementation restriction, **not** that a user test was independently executed for this candidate.

## Desired outcome

Export the complete accepted city to PNG at specified size/scale independently of the current viewport, without modifying the active camera.

## Draft acceptance criteria

- [ ] Provide whole-city framing, chosen size and clear handling of background/layers.
- [ ] Use tiled or bounded rendering where necessary; avoid crashing browsers due to oversized canvases.
- [ ] No change to live camera, selected objects, editor state or stored project.
- [ ] Export offline on Firefox and Chromium; verify content bounds, transparency/legend options as explicitly selected.

## Dependencies and design boundary

Standalone renderer/camera API and D03 capacity sizing.

**Owner decision needed:** Choose export target: entire surveyed boundary, developed area, or configurable crop; settle pixel caps before implementation.

## Preservation and verification gates

Retain deterministic generation, one authoritative accepted city, preview/Cancel isolation, independent full validation before atomic Apply, stable provable identities, protected and unknown authored metadata, appropriate scoped Undo/Redo, and safe offline project round-trip. Any required schema migration, existing CI policy change, release or Pages publication needs **separate authorization**. Use targeted tests during development and full six-runner CI for the review-ready PR.

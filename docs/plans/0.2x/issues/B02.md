# [B02] Extend property splits beyond straight frontage-to-rear dividers

> **Published tracking proposal:** [#100](https://github.com/xbwtyz/Mappo/issues/100) records this limitation or possible capability. This is **not** an approved implementation or assigned release.

**Group:** B · **Classification:** Confirmed feature restriction · **Suggested priority:** P2 · **Version:** Unassigned

## Current behavior and user impact

Owners cannot make arbitrary angled, L-shaped or multi-step boundary divisions of a single parcel.

**Current technical limitation:** E2 supports a single straight division through supported convex quadrilateral frontage geometry.

## Reproduction / evidence collection

Attempt to split a four-corner property with an angled or stepped cut that does not fit the current frontage-to-rear design.

Reconfirm against the version planned for implementation, recording a deterministic seed, relevant IDs, browser and actual error message. The source reference indicates an implementation restriction, **not** that a user test was independently executed for this candidate.

## Desired outcome

Permit user-defined safe parcel splits while proving access, polygon coverage and ownership of plots/buildings.

## Draft acceptance criteria

- [ ] Specify legal divider shapes and minimum child frontage/access policy.
- [ ] Both successors tile the source exactly without overlaps, gaps or orphaned building memberships.
- [ ] Existing names/IDs and protected custom metadata follow explicit lineage/consent policy.
- [ ] Preview impacts; one atomic Apply; Undo/Redo; offline project round-trip.

## Dependencies and design boundary

B01 general property polygons and reusable exact polygon partitioning.

**Owner decision needed:** Should every child require direct road frontage, or can internal lots rely on audited access easements?

## Preservation and verification gates

Retain deterministic generation, one authoritative accepted city, preview/Cancel isolation, independent full validation before atomic Apply, stable provable identities, protected and unknown authored metadata, appropriate scoped Undo/Redo, and safe offline project round-trip. Any required schema migration, existing CI policy change, release or Pages publication needs **separate authorization**. Use targeted tests during development and full six-runner CI for the review-ready PR.

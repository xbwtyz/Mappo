# [B04] Add flexible plot subdivisions and multi-divider transactions

> **Draft only:** Proposed future GitHub Issue. No GitHub Issue has been created yet.

**Group:** B · **Classification:** Confirmed feature restriction · **Suggested priority:** P2 · **Version:** Unassigned

## Current behavior and user impact

Plots are ordered frontage-to-rear strips and only one count change can be applied at a time.

**Current technical limitation:** E4 assumes canonical four-corner plots and one divider/count change per Apply.

## Reproduction / evidence collection

Try dividing an irregular parent into non-strip shapes or adding several plot dividers in a single draft.

Reconfirm against the version planned for implementation, recording a deterministic seed, relevant IDs, browser and actual error message. The source reference indicates an implementation restriction, **not** that a user test was independently executed for this candidate.

## Desired outcome

Allow flexible plot partitioning while ensuring exact property coverage, building membership and safe history.

## Draft acceptance criteria

- [ ] Specify allowable plot topology and minimum usable area/access.
- [ ] Result covers property exactly, preserves identity where provable and records retired/source lineage.
- [ ] Buildings, courtyards and entrances remain assigned to valid plots, with explicit conflict decisions.
- [ ] Multi-step preview has one atomic Apply and one Undo/Redo transaction; portable round-trip.

## Dependencies and design boundary

B01 and B02; B03 for merges coupled to plot membership.

**Owner decision needed:** Separately decide arbitrary plot shapes and multi-action batching; they need not ship together.

## Preservation and verification gates

Retain deterministic generation, one authoritative accepted city, preview/Cancel isolation, independent full validation before atomic Apply, stable provable identities, protected and unknown authored metadata, appropriate scoped Undo/Redo, and safe offline project round-trip. Any required schema migration, existing CI policy change, release or Pages publication needs **separate authorization**. Use targeted tests during development and full six-runner CI for the review-ready PR.

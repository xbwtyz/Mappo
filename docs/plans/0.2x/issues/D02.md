# [D02] Investigate residual road-editor frame hitches and worker fallbacks

> **Evidence-gated tracking investigation:** [#107](https://github.com/xbwtyz/Mappo/issues/107) is not a confirmed current regression. A new reproducible case is required before any implementation.

**Group:** D · **Classification:** Known performance caveat; not proven current bug · **Suggested priority:** Conditional · **Version:** Unassigned — evidence gate first

## Current behavior and user impact

Occasional 100–183 ms frame gaps were measured on large-city tests; worker-disabled or some ordinary road paths may still validate synchronously.

**Current technical limitation:** Previous ~1 second UI freezes in issues #44/#46 were fixed or not reproduced; those issues are closed after owner review.

## Reproduction / evidence collection

Reproduce on a supported desktop with a seed, edit operation, browser version, trace, input latency and whether worker initialized; benchmark P7/H3 comparably.

Reconfirm against the version planned for implementation, recording a deterministic seed, relevant IDs, browser and actual error message. The source reference indicates an implementation restriction, **not** that a user test was independently executed for this candidate.

## Desired outcome

Only if a meaningful current freeze is reproduced, identify the precise synchronous hotspot and reduce user-visible stalls.

## Draft acceptance criteria

- [ ] Attach a new reproducible performance case, profile and baseline before reopening optimization work.
- [ ] Distinguish preview readiness time from actual blocked input/frame delay.
- [ ] Avoid speculative thresholds and require same-runner before/after comparisons.
- [ ] Preserve fallback correctness, stale-draft cancellation and accepted-state invariants.

## Dependencies and design boundary

Evidence-gated; could be revisited during 0.2.1 if the new topology worsens latency.

**Owner decision needed:** Create a tracking note first; open a new performance bug only on reproducible user impact.

## Preservation and verification gates

Retain deterministic generation, one authoritative accepted city, preview/Cancel isolation, independent full validation before atomic Apply, stable provable identities, protected and unknown authored metadata, appropriate scoped Undo/Redo, and safe offline project round-trip. Any required schema migration, existing CI policy change, release or Pages publication needs **separate authorization**. Use targeted tests during development and full six-runner CI for the review-ready PR.

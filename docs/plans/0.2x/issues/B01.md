# [B01] Support irregular multi-vertex and concave property boundaries

> **Published tracking proposal:** [#99](https://github.com/xbwtyz/Mappo/issues/99) records this limitation or possible capability. This is **not** an approved implementation or assigned release.

**Group:** B · **Classification:** Confirmed geometry-model restriction · **Suggested priority:** P1 · **Version:** Unassigned — foundational parcel wave

## Current behavior and user impact

Parcel operations only handle convex four-corner properties, so L-shaped, five-sided and other valid city parcels are difficult or impossible to model.

**Current technical limitation:** Editor and reflow routines require exactly four boundary points and frontage frames; plot subdivision assumes strips.

## Reproduction / evidence collection

Select or import a valid polygon with five corners / a concave corner; attempt existing property geometry editing or split.

Reconfirm against the version planned for implementation, recording a deterministic seed, relevant IDs, browser and actual error message. The source reference indicates an implementation restriction, **not** that a user test was independently executed for this candidate.

## Desired outcome

Allow validated simple irregular property polygons while preserving frontage, plots, existing buildings, IDs and road clearance.

## Draft acceptance criteria

- [ ] Agree on polygon class (simple concave, holes? multi-frontage?) and ownership/frontage rules before changing code.
- [ ] Build shared polygon, area, containment, setbacks and parcel tiling validation reused by editors and generators.
- [ ] No authored geometry or plot/building membership is silently discarded or reassigned.
- [ ] Approved geometry is saved, restored and edited across all relevant modes; keep old four-corner fixtures passing.

## Dependencies and design boundary

A01/A06 road-face changes; unlocks B02–B04 and B05.

**Owner decision needed:** Choose support level for irregular shapes: convex N-gons first vs general simple concave polygons; decide whether parcel holes are in scope.

## Preservation and verification gates

Retain deterministic generation, one authoritative accepted city, preview/Cancel isolation, independent full validation before atomic Apply, stable provable identities, protected and unknown authored metadata, appropriate scoped Undo/Redo, and safe offline project round-trip. Any required schema migration, existing CI policy change, release or Pages publication needs **separate authorization**. Use targeted tests during development and full six-runner CI for the review-ready PR.

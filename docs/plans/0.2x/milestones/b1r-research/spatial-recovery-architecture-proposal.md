## 1. Evidence and limitations

See [compression follow-up](compression-followup.md) for exact research methods, failures, witness ledgers and hosted runs R1–R30. Original B1R [contract](../0.2.24-adaptive-reconciliation-b1r.md) remains binding in production. The 800-case original study yielded empirical strict union 627/800, with production acceptance requirements; do not confuse strict preservation and relaxed recovery.

- R26–28 independently solve all 18 compression scenarios, ten without retirement. R28 proves exact cooperative parity, not browser latency; 17 property/21 plot/26 building retirements across scenarios. R24 individually optimized witness set 10/14/25; R25 adds 2/2/10 without restoring retired identities. R29 improves both reverse cases, combined best R28+R29 13/17/26, not yet a unified run. No proof of global optimality.
- R17 conservative area bound rules out full building preservation for two reverse blocks even at 20% shrink. No automatic change to topology, setback or ownership constraints. R9 plot topology, R14 incremental moves, R15–16 ownership exchanges did not establish benefit on this corpus; defer.
- R28 max individual tick 397.7ms (verification), so moving only geometry to worker is insufficient. R30 actual Node worker test exact parity 3/3 and lifecycle checks, not browser acceptance; response 4.5–4.7 MB including two JSON snapshots. Host heartbeat is not a frame-rate or latency SLA.
- R29 improvements, original 800 cases, actual private Cinderdale save, new seeds/geometry classes, malformed inputs, browser offline QA all remain integration gates. No private save may be uploaded publicly. Existing production code unaffected.

## 2. Proposed decisions — owner approval required

| ID | Recommended A | Alternative B / trade-off |
|---|---|---|
| SRE-01 | Extend B1R operation, context, policy, budgets and validators behind shared recovery contracts; road-group adapter first. | Separate replacement engine; faster initial isolation, duplicate invariants and maintenance. |
| SRE-02 | Strict and packing first; explicit per-intent opt-in for alternate frontage and scaling search; no relaxed candidate auto-applied. | Automatically preview relaxed candidates; convenience but changes defaults and increases unexpected edits. |
| SRE-03 | Separate user-requested building and parcel retirement search, explicit exact destruction authorization; restoration and exchange within permitted scope. | Single broad destruction permission; simpler UI but less control. |
| SRE-04 | Optional regeneration, separately enabled, review exact additions and retirements; new IDs never masquerade as restored originals. | Regeneration automatically included in destructive candidate; potentially surprising reconstruction. |
| SRE-05 | Generated, known, dependency-free content only for new concessions; preserve existing authored reshape contract; unknown and protected objects fail closed. | Widen to authored or dependent entities; not supported by research, defer. |
| SRE-06 | Versioned lexicographic/Pareto cost vectors and explicit alternatives, strict candidate never displaced by relaxed candidate without user choice. Prefer nonincreasing retirement counts, then total footprint loss and fewer frontage/scale changes within same authorized tier. | One weighted scalar objective; simpler ranking but arbitrary cross-entity trade-offs. |
| SRE-07 | Run entire search and candidate verification in reusable offline worker; latest request wins, cooperative progress, hard termination on supersession. Retain synchronous strict fallback; expensive relaxed search unavailable if worker unsupported until safe alternative exists. | Run on main thread with time slicing; research shows indivisible stalls. |
| SRE-08 | Versioned typed delta and compact preview geometry over worker boundary; reconstruct from exact accepted snapshot, compare fingerprint, independently validate before Apply. Full snapshot fallback only if needed and measured. | Transfer two full candidate snapshots as research does; easier but large payload and memory cost. |
| SRE-09 | Keep Schema 10, portable 1, workspace 1; audit current ID allocation/history/archive first. Reserve IDs against accepted entities, pending delta and known historical IDs; require separate owner decision if durable no-reuse needs new persisted data. | Introduce schema migration immediately to store allocator state; premature without contract audit. |
| SRE-10 | Reuse universal Review/Apply/Undo lifecycle; show explicit per-kind counts, IDs, frontage, scale bounds and regeneration; re-review if candidate changes. | Separate recovery wizard/history; duplicates existing UI and transaction model. |
| SRE-11 | Bounded deterministic progressive search; improve incumbent; distinguish exhausted, budget-limited, cancelled and proven hard refusals; no wall-clock-based geometry decisions. | Unbounded exhaustive search; impractical for interactive editing. |
| SRE-12 | Permanent layered regression gates, first narrow integration then quality/performance polish and corpus qualification. | Broad implementation across water/terrain/3D now; premature generalization and regression risk. |

Recommendations are provisional, not automatic policy changes. Default strict behavior preserved. Owner may authorize flexible search without authorizing its candidate; destruction and creation are separate from consent to search.

## 3. Architecture and data contracts

Extend existing reconciliation-operation.js, reconciliation-policy.js, reconciliation-context.js, reconciliation-budget.js, reconciliation-preservation.js, reconciliation-demolition.js and editor road-application/road-preview contracts. Inspect exact sources before defining file moves. New internal interfaces should have real callers and no runtime plugin API. Do not paste research source-patching harnesses into production.

- Operation adapter: pure normalized intent {type, version, editedRefs, acceptedRevision, acceptedFingerprint, geometry}, immutable affected scope/dependency edges, typed refs {kind,id}. Only topology-preserving connected road translation implemented in this milestone. Keep existing authored parcel decisions. Later lake/river/terrain/wall/district adapters supply their own invariants. Canonical accepted 2D city remains single source of truth; no 3D schema or engine now.
- Capability/constraint registry: classify generated/fixed/unknown/authored/dependent; independent capability evaluation from accepted records and explicit per-intent policy. Hard geometry/identity/ownership/access/dependency checks cannot be converted into score penalties. Unknown kind/version unsupported. No automatic cross-block relocation, cross-owner transfer, reflection, topology change, protected destruction, plot topology changes or new assets. Dimension-aware interfaces, use existing 2D primitives.
- Strategy descriptors: {id,version,operations,requires,preconditions,iterateCandidates}. Strategy proposes only detached data. Coordinator controls allowed strategies and deterministic budget hierarchy, not trusted to grant permissions. Existing strict strategies remain authoritative; extract packing, adjacent frontage, targeted uniform scaling (5/10/20% research bounds; owner chooses UI defaults), eligible retirement plans, batched/shell restoration, local exchanges and optional regeneration. Separate candidate enumeration from geometry, score, transport and scheduling. Cache only exact snapshot/intent/permissions/strategy-version keyed reusable facts; never reuse stale decisions.
- Candidate envelope: accepted identity, revision and fingerprint; intent fingerprint; policy fingerprint; solver version; exact deterministic typed delta including removed/created/modified records and explicit derived membership/summaries; cost vector and diagnostics; candidate fingerprint. Review ledger independently reconstructed from accepted-to-candidate diff. Keep gross retirement distinct from regeneration and net counts. Missing, duplicated or unknown entity refs and unsupported deltas refuse. Candidate geometry and all survivor fields verified, including canonical S10 components/regions, occupancy, plot tiling, frontage, access and provenance.
- Independent validation: trusted validation pipeline derives eligibility, scope, geometry, dependency graph, authorized transformations and exact deltas from original and candidate. Does not rely on solver-declared capability, status, review ledger, or cost. Verify untouched/unknown fields, immutable infrastructure, reference protection, exact removals and fresh additions, area and route constraints, archive, stored-project validity. Verify worker output for preview; fresh independent Apply gate binds exact accepted identity/revision/intent/policy/candidate/ledger authorization and reconstructs from current accepted state. No partial application. Do not rerun expensive search synchronously merely to obtain same candidate; validate selected witness, with deterministic replay in tests.
- Cost: keep strict tier preferences and nonincreasing destruction counts; within explicitly allowed recovery compare typed retirement counts, gross demolished footprint, scaled footprint loss, displacement/rotation/deformation, changed frontage and access, newly generated footprint and count. Avoid net count hiding destroyed originals. Same-count improvements favor lower area loss, then fewer frontage/scale concessions. Retain incomparable alternatives with bounded shortlist rather than asserting a universal weighted optimum. Default comparator and shortlist size require review.
- Worker protocol: versioned request/session/job identity, accepted fingerprint/revision, typed intent, permission snapshot, deterministic limits. Progress summaries only, bounded publication, monotonic work counts, no stale partial geometry. Reuse existing junction worker lifecycle and standalone bundler patterns; hard stop obsolete jobs, separate cooperative stop retaining verified incumbent from cancel/reset which invalidates authorization. Unknown/malformed messages rejected; stale progress/results ignored. Use clone-safe data and no dynamic external code/network. Worker initialization/transfer costs and final validation measured separately. Do not pretend 8ms soft slices are hard bounds.
- Identity allocation: audit accepted IDs, existing manual allocators, archive/history, deletion and save/reopen behavior. Reserve fresh typed IDs deterministically for a candidate, avoid original/retired/pending collisions and preserve known historical references. Do not silently reuse IDs to inflate restoration. No new persisted field without schema/format review. Explicit test repeated retire/regenerate/undo/redo/branch/reopen. If current storage cannot prove durable uniqueness, block production regeneration pending approved allocation decision.

## 4. Proposed UX and permission model

Normal edit stays strict and non-destructive. After supported strict/packing refusal show actionable reason and options: flexible frontage, bounded resizing, search destructive alternatives (building and parcel scope separately), optional rebuild vacant land. These are search permissions, not Apply authorization. Authored/protected/unknown and out-of-scope records remain fixed. Show verified candidate before accepting: exact retired IDs, scaled IDs/factors, old/new frontage, restored identities, created IDs, original versus new counts and footprint metrics, impacted blocks, unsupported constraints and budget status. Offer strict or less disruptive alternative where available. Search progress and Stop keep last verified candidate for same current intent only; Cancel/Reset/new edit discard authorization and obsolete job. Apply explicitly confirms exact selected ledger and validates independently; one accepted transaction through universal Undo/Redo and portable roundtrip. No new hotkey or duplicate history. UI copy/permission defaults and interaction details to be specified in approved P1–P5 plan.

## 5. Proposed implementation checkpoints (scope, not authorization)

P1 — Shared contracts and safety. Read current main and reconcile roadmap/docs under approval. Introduce shared typed descriptors and independent delta/capability checks while preserving existing strict behavior. Baseline parity, malformed/unknown refs, protected/authored dependency tests. Audit allocator and decide regeneration feasibility. No production policy relaxation yet.

P2 — Preservation/flexible strategies. Integrate packing and explicit adjacent-frontage/targeted-scale capabilities using existing geometry/access/occupancy validators. Preserve all 627 original strict witnesses under strict policy, no strict regressions; prove every new permission independently. Freeze candidate/delta tests and negative tamper fixtures. No demolition implied by flex.

P3 — Destructive recovery/restoration/regeneration. Integrate explicit building/parcel retirement, batched and shell restores, R24/R29 local exchanges, same-set concession comparisons, optional additive generator adapter if ID contract approved. Complete independent oracle-free 18-case corpus, compare per-case quality against R28 and R29 and publish any remaining trade-offs. Preserve strict candidates separately. Exact review ledgers, protected content, generation provenance, no reused IDs, deterministic replay, undo/redo/save/reopen. No inferred permission from search result.

P4 — Worker and review integration. Offline compiled Blob/Web Worker using existing lifecycle, responsive progress and cancellation, latest intent/revision wins, compact transport, independent Apply validation, unified history. Chromium and Firefox file://; no requests, no mandatory server. Fallback does not run long relaxed search on editor thread. Profile input latency, initialization, transfer, time to first verified candidate, completion P50/P95/max, validation and Apply time, memory, progress overhead, cancellation. Define numerical performance gates using measured baseline and owner-reviewed limits rather than guessing laptop/browser SLA.

P5 — Qualification. Exact original 800-case corpus, retain 627/627 original strict preservation successes and prior accepted B1R reviewed demolition coverage; independently verify no invalid acceptances, no unauthorized modification, exact identity/metadata preservation. Repeat across morphologies, sizes, edited/protected/dependent Schema10 fixtures, irregular/multipart/courtyard structures, valid and invalid topology, worker errors/late messages and repeated transactions. Run original private Cinderdale locally only with explicit exception if needed; no public upload. Require 18/18 integrated independent successes, publish comparison with R24/R25/R29 quality and performance, unresolved cases and proof limits. Compile unchanged standalone format, root/dist byte-identical, full six-runner CI and aggregate exact head. Review PR; separate merge approval, exact-main CI, no release/tag/Pages without separate approval.

## 6. Go/no-go

Research readiness is established, production readiness is not. No hidden assumptions of successful future tests. Owner first approves SRE-01–12 (or alternatives); then review detailed P1–P5 data contract, files, dependency graph, fixture matrix, numeric acceptance and permission UI. Separate explicit authorization before production implementation on fresh verified-main branch. Research branch remains evidence, not wholesale merge candidate. If any strict witness regresses, an unauthorized entity changes, allocator safety is unproven, offline behavior breaks, or validation fails, stop at checkpoint and review. Do not waive safeguards for a green headline.

# 0.2.22-dev A5 — History and workflow improvements

The approved A5 scope puts district and defense edits in the shared accepted-city history, gives Reset Preview its own shortcut, and displays history errors beside the relevant control on hover and keyboard focus.

| Command | Map shortcut | Result |
| --- | --- | --- |
| Undo | Ctrl/Cmd+Z | Reverse the latest applied city transaction. |
| Redo | Ctrl/Cmd+Y | Replay the latest undone city transaction. |
| Reset preview | Ctrl/Cmd+Shift+Z | Run the current editor's existing preview reset action where supported. |

Focused inputs keep native editing shortcuts. A blocked history command retains the next action label and explains the blocking draft. The toolbar and History panel use the same transaction labels. The draft's existing validation and confirmation rules still govern its Reset and Apply actions.

## Implementation and acceptance

| Checkpoint | Acceptance |
| --- | --- |
| P1 · Command routing | Toolbar and shortcuts resolve the same accepted transaction. Reset affects only the active preview. Blocked Undo leaves the city and draft untouched. |
| P2 · District history | District rebuilds, names, colors and block moves record one transaction each. History restores the complete accepted membership and removes stale district or block selections when necessary. |
| P3 · Defense history | Build, rebuild, enable and disable record one transaction each when geometry or accepted settings change. Undo/Redo restores walls, gates, towers and accepted settings. |
| P4 · Labels and diagnostic box | Available actions identify the transaction. A disabled Undo/Redo can be focused for its explanation. The same explanation is available on hover. |
| P5 · Verification | Verify interleaved building, district, defense and property transactions, saved snapshots, offline Firefox/Chromium, standalone parity and all six CI runners. |

District and defense workspace snapshots retain their existing representation in Schema 10, portable format 1 and workspace version 1. The chronological history is session-only. When a project is opened, its saved district and defense snapshots are available as explicitly labeled restore actions in the History panel. A restore validates the project and is recorded as a new reversible transaction. When undoing or redoing a live district or defense action, the journal also restores the affected compatibility stack so the next save reflects the accepted position.

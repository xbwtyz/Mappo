## Search strategy and authority
Build serial multi-strategy orchestration first. Strategies are specialized, registered with stable IDs, versions, capability/permission prerequisites, typed inputs, measurable cost, deterministic checkpoint/output semantics and independently replayable candidates. Initial strategies may include neighbor geometry, parcel recovery, authorized topology restructuring, verified scope expansion, restoration and mixed sequences. P1–P3 derive the portfolio and scheduler from actual blocker evidence, existing RTRE/SRE contracts and research; do not build speculative solvers merely to fill a list. Hard validity, exact selected intent, scope bounds, permissions and protected identity checks precede ranking. Use deterministic bounded diversification and feedback from verified blockers to reduce redundant dead-end work. Distinguish known local impossibility/permission limits from incomplete bounded search. Search quality does not change editing authority. Preserve first verified incumbent and improve under approved ranking; never replace it with an unverified result. Stagnation uses work/phase evidence, repeated states and deterministic improvement tests, not wall-clock deadlines. Detailed thresholds/profile weights to be qualified before activation.

## Worker and deterministic budgeting contract
Design UAEF scheduler with immutable or isolated accepted snapshots; serializable versioned tasks and stable ordering, deterministic budget slices, per-task work/expansion accounting, and coordinator-owned aggregation at logical barriers. One root operation budget across all searches; reserved work must not be double-spent or duplicated when workers fail, cancel or retry. Redistribute only verified unused work at deterministic checkpoints based on results in logical order, not which CPU finishes first. Account scope/index and verification work under applicable existing contracts; independent host review/Apply remains mandatory and separate where existing policy requires. Preserve existing budget and safety contracts until a specifically approved change. No shared mutable accepted city or direct worker publication. Host validates all untrusted messages and discards stale operation/revision/session results.

Worker options proposed Automatic (default after qualification), 1, 2, 4, and 8 (advanced only if supported and qualified). Actual Auto heuristic, allowed cap, memory thresholds, CPU reservation, worker count exposure and fallback behavior must be researched and explicitly bounded in implementation plan; do not assume hardwareConcurrency is physical cores or guarantee memory estimates. Cap workers against measured memory and responsiveness. Avoid copying entire city per task when safe; reuse per-worker immutable input and derived caches keyed to snapshot/rule versions, transfer compact payloads where practical. Offline single HTML and Firefox/Chromium support remain required; do not require cross-origin isolation, SharedArrayBuffer, server, GPU or network. Use serial worker fallback without running expensive synchronous search on UI thread. Handle worker failure explicitly with safe bounded retry or refusal; no silent partial success.

For identical accepted snapshot, intent, permissions, strategy/profile versions, quality and root budget, a normally completed search should yield equivalent final ranked candidate, typed identities, lineage and independently verified geometry across qualified worker counts and supported engines. Preserve locked exact fingerprints and existing strict results. Measure deterministic work/expansion accounting separately from elapsed time; preserve existing exact-accounting expectations where applicable. Use fixed logical batches, stable reductions/tie-breaks, and deterministic allocation; qualify across adversarial task completion orders and repeated runs. Explicit user Stop or cancellation may yield different intermediate verified incumbents; no claim of identical intermediate elapsed-time state. Stop/Continue must preserve the same logical checkpoint/budget, and Review best verifies the exact captured incumbent. Cancel/reset/intent or revision change suppresses all old results, reservations and review tokens. Keep progress in logical work units, UI responsive and accessible.

## Quality and rollout
Fast seeks verified candidate within limited exploration; Standard balances effort and quality; High explores alternative strategies and restoration; Extended is an experimental bounded expansion, not exhaustive or unbounded. Existing Standard/High budgets and current mounted eligibility remain unchanged pending research and separate detailed budget/quality activation approval. Fast/Extended numerical budgets, mode compatibility, defaults and any permission interaction must be defined and qualified; no automatic destructive escalation. Stage serial reference, detached deterministic scheduler, detached worker pool parity, representative mounted pilot, then consider Auto default only if measured benefit and safeguards pass. If a worker pool is ineffective, retain serial mode and report; do not lower safety or recovery targets to ship parallelism.

## Qualification and phase integration
P1 structured blocker/strategy diagnostics; P2 dependency discovery and constraint-aware work evidence; P3 serial portfolio, task/budget contracts, deterministic redistribution, bounded search and research comparisons; P4–P6 domain-specific strategies with existing independent topology/ownership checks; P7 integrate coordinator and detached reusable bounded worker pool with serial-reference parity before mounted activation; P8 offline worker/UI controls, cancellation, fallback and accessible progress; P9 full qualification including serial/parallel determinism and resource scaling.

Predeclare representative dry and mixed-landscape, small/large, easy and difficult, feasible/refused fixtures. Compare serial strategy intelligence to existing baseline at matched budgets; compare parallel vs serial at identical strategy/version/budget (separate from increased-quality budget experiments). Record candidate fingerprint/IDs, verified ranking, outcomes/refusal reasons, useful work/expansions, time to first verified incumbent and final review, total work, wall time, worker initialization/serialization/verification overhead, peak memory where measurable, pointer/frame responsiveness, progress and cancellation delay. Test 1/2/4 and 8 where actually supported, repeat/reorder completions, test worker creation failure, low-resource fallback, cancel/Stop/Continue/reset, stale packets, malformed or over-budget evidence, no unauthorized writes and no duplicate work accounting. Report missing measurement explicitly. Compare on matched environments; do not generalize hosted timings to owner hardware. No required production parallel default until a measurable benefit with no regression in qualified outcomes, safety or responsiveness is demonstrated and reviewed. Existing 10,000-scenario qualification, mandatory 22 CI jobs and historical regression coverage remain intact. Heavy benchmarks remain opt-in. No numeric speedup promises; no new CI workflow policy or runtime change authorized here.

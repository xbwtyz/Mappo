## OPT-01 batching
Classify dependencies, affected systems, reversibility, and risk. Group low-risk independent documentation/tests/diagnostics in 3–5 compatible tasks; medium-risk closely related tooling/UI in 2–3; high-risk geometry, preservation, topology and identity independently. Critical safety, schema, destructive-policy or publishing changes require separate approval and dedicated qualification. Sizes are heuristics, not quotas; split if failures cannot be isolated or acceptance differs. Each batch records scope, checks, impact and rollback. Verify exact head before continuation; preserve full review-ready/main CI. No parallel independent feature workstreams.

## OPT-02 bounded approvals
Record goal, authorized tasks and branch, affected files/systems and permissions, acceptance criteria, evidence, exclusions, stop conditions, expiration and rollback. Explicit approval covers in-scope implementation, tests, documentation, diagnosis and corrections while the owner requests continuation. Green is evidence, not merge permission. No unattended execution, scope expansion, unapproved policy/schema/safety change, automatic merge or publishing. Stop for ambiguity, failed acceptance requiring a policy change, completion or mandatory gate. Approval expires at completion or mandatory stop. Record actual approval, not inferred consent.

## OPT-03 persistent checkpoints
Write versioned JSON in docs/development/checkpoints/ at verified milestones. Record exact source SHA (not self-referential commit), branch/PR, version, approval scope, completed/pending tasks, decisions, blockers, evidence, artifact identity, rollback and next action. Independently fetch live GitHub PR/ref, exact-head runs/jobs and tree before using it. Read-only command (requires authenticated GitHub CLI): `node scripts/development/checkpoint.mjs docs/development/checkpoints/sre-e2-paused.json`. Fail closed on stale or incomplete evidence; no authority granted. Initial version supports paused draft focused-only checkpoints, not full-gate states. Test counts in the record originate from the recorded job logs; CLI checks run/job conclusions and artifact IDs, not test log contents. Future contracts must distinguish evidence types.

## OPT-11 performance tracking
Run `node scripts/development/metrics.mjs docs/development/metrics/p0-baseline.json`. Keep full-main and fast-draft separate. Full successes require both Node shards, four browser jobs and aggregate; fast workflow-only observations are labeled separately from job-confirmed successes. Failures, canceled and incomplete cases are visible. Wall duration is updated minus created timestamp, including queue/teardown; runner minutes sum non-skipped recorded job intervals, not billed minutes. Report median, nearest-rank p90, sample sizes, missing data. Do not compare different workloads as controlled speedups. Measure approval/handoff effort and duplicate workloads prospectively; unknown stays unknown. Time-of-day comparisons require matched workloads.

# Mappo Milestone 3H — Property-first Building Structure Editing

**Branch:** `feature/building-management-3h` · **Standalone checkpoint:** `0.1-dev.3he`  
**Base:** merged 3G-D PR #9 · **Status:** Awaiting separate owner merge approval.

## 3H-A — Property-first placement

The owning property remains the anchor. A property Inspector action opens an isolated placement preview; numeric frontage/inward placement or clicking/dragging the ghost repositions it. A new, collision-resistant `BLD-MAN-…` ID is allocated without recycling deleted generated IDs. Nothing is serialized until explicitly applied.

## 3H-B — Preset shapes and controls

Rectangle, L, courtyard, and T footprints are defined in the property's own local frontage/inward frame and can be rotated, resized and moved. Selectable building use (house, shop, workshop, inn, warehouse, guildhall or temple) is stored with accepted records. A distinct map ghost displays status and parent property context.

## 3H-C — Schema-safe Apply

Add/replace candidates are cloned and validated through existing 3G-C exact polygon, property membership, occupied-plot and frontage-road checks. The entire candidate then passes project schema-9 validation and a portable create/encode/decode round trip. The accepted project is assigned atomically. Replacements preserve building ID and existing custom identity; additions create unique IDs and a correct `property.buildingIds` relationship. The road network and properties are not altered. Invalid placements stay editable and never change accepted city geometry.

## 3H-D — Delete/replace and structural history

Delete requires explicit confirmation in browsers and removes a building only, preserving its property. Structural Undo/Redo uses independent, validated project transactions with a maximum of 20 session entries. Operations are scoped to the selected property and recheck membership and current record continuity. Accepted geometry/IDs survive project save/load and recovery, but placement previews and Undo/Redo stacks do not; reload and regeneration clear them. A structure edit clears older geometry Undo history to prevent stale references. Cross-property transfer remains unsupported.

## 3H-E — QA and distribution

- `tests/building-structures.test.js`: shapes, valid and invalid replacements, add after deletion, structural Undo/Redo, compiled UI Inspector and save/load invariants.
- `scripts/building-browser-qa.mjs`: property-first Add preview, ghost preset changes, cancellation and unchanged accepted city across the Chromium/Firefox viewport matrix.
- Existing tests and project fixtures retained, including schema-9 migrations and the geometry-only 3G functionality.
- `index.html` and `dist/mappo-0.1-dev.3he.html` generated by `npm run build`, byte-identical and committed together.
- The official CI must pass before merging; no unattended merge.

## Known limitations

Properties are usually largely occupied, so a valid new 5-unit footprint may not fit without removing or shrinking existing structures. Building positions and angles are numeric as well as draggable; no new property setbacks are introduced. Structural history is in-memory and cannot be recovered from a portable project. If later accepted edits to the same property invalidate a history target, Undo is disabled rather than overwriting unrelated geometry.
